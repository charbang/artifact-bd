Module 02 / Non-Relational Architecture

NoSQL FLEXIBLE

NoSQL no representa un único tipo de base de datos.

Incluye diferentes modelos como documentos, clave-valor, columnas y grafos. Su flexibilidad permite adaptar la forma de almacenar información a diferentes necesidades.

01 / MODELS

NoSQL no es uno.

Existen diferentes modelos NoSQL. Cada uno organiza la información de una manera diferente.

{ }

Documentos

Los datos se almacenan en documentos, normalmente con estructuras similares a JSON.

Ejemplo: MongoDB.

K/V

Clave-valor

La información se representa mediante pares de clave y valor.

Ejemplo: Redis.

COL

Columnas

Organiza la información utilizando familias de columnas.

Ejemplo: Cassandra.

GRAPH

Grafos

Representa información mediante nodos y relaciones.

Ejemplo: Neo4j.

03 / SCALE

¿Cuándo conviene?

NoSQL puede resultar interesante cuando existen estructuras variables, grandes volúmenes de información o necesidades particulares de distribución y escalabilidad.

Señales

  • La estructura cambia frecuentemente.
  • Existen grandes volúmenes de datos.
  • Los datos llegan rápidamente.
  • Los registros pueden ser diferentes.
  • Se necesita distribución.

Posibles escenarios

  • Redes sociales.
  • Internet de las cosas.
  • Chat en tiempo real.
  • Sistemas de caché.
  • Catálogos y recomendaciones.
04 / POLYGLOT

Combinar tecnologías.

Un sistema puede utilizar diferentes gestores dependiendo de la función que necesite resolver.

TRANSACTIONS

PostgreSQL

Compras, clientes y pagos.

DOCUMENTS

MongoDB

Catálogos, reseñas y datos flexibles.

CACHE

Redis

Sesiones, caché y datos temporales.

05 / DECISION

Primero el problema.

La elección de una tecnología debe partir de las necesidades del sistema.

¿Existen relaciones fuertes entre los datos?

Si las relaciones, la consistencia y las transacciones son fundamentales, una solución relacional puede resultar apropiada.

¿La estructura cambia frecuentemente?

Una estructura flexible puede hacer interesante el uso de un modelo NoSQL, especialmente cuando también existen grandes volúmenes o necesidades de distribución.

¿Se pueden utilizar ambas?

Sí. La persistencia políglota consiste en utilizar diferentes tecnologías según las necesidades concretas de cada parte del sistema.
